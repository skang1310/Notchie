# Notchie stability, activity scheduling, displays and idle work — v42

Scope authorized by the user: improvements 2, 3, 4, 8 from the whole-app review, plus renaming the installed app from DynamicNotch to Notchie. No additional product features or settings were introduced. Existing GPL/upstream notices, bundle identifier, preferences and permission opt-ins remain. Lazyweb tools were unavailable; the existing native surface/components were reused.

## 2. Open/close interaction

Removed the independent six-second Quick Tools auto-dismiss task: it could fire during a later interaction when the pointer happened to be outside the panel. Existing hover/outside-click/pin behavior remains in charge. Pending expansion is explicitly canceled when the pointer leaves before expansion, outside click occurs, the presentation changes, or display geometry is invalidated. A delayed expansion validates its original presentation ID before executing. Menu tracking is depth-counted; nested menus suspend hover/outside dismissal. Hover dismissal uses a 180ms exit grace after the opening protection period and checks active press, menu, scrolling and actual pointer bounds. Delayed hover/press actions are invalidated when content/display changes.

## 3. Priority and safe restoration

Ordinary notifications and background activity changes cannot replace an expanded interaction. Ordinary deferred alerts are coalesced by ID, capped at eight, and expire using original arrival time rather than replaying stale alerts after a long session. Collapsing reconciles the currently highest-priority still-active activity. Timer completion and system-critical presentations may interrupt, and ordinary alerts cannot replace these while they are displayed. System-critical activities outrank the manually opened hub. Running timer default priority is above calendar, while user overrides remain supported. Equal-priority arrivals retain the current activity instead of alphabetical churn. Queued activity updates coalesce by stack ID; replaced/ended activities are re-resolved after transition delays to prevent resurrection. Transition waiters use continuations instead of 10ms polling.

## 4. Display lifecycle

Screen changes and display/system wake trigger immediate geometry recovery plus one cancellable 250ms settling pass. Workspace activation/space events coalesce over 50ms. Unchanged frames are not re-applied; geometry migration invalidates pointer actions and stale drag-registration callbacks. Canvas fits small displays; content scales uniformly to the selected screen's bounds, and outside-click bounds include the actual scale and island offset. Negative screen origins retain top-center anchoring. Built-in selection falls back to a connected display only when the existing automatic-switch setting permits it, and returns to built-in when available. Fullscreen visibility state is computed in the window policy rather than querying SkyLight from every SwiftUI body evaluation; invisible surfaces stop hit testing. Existing fullscreen/app hide settings remain authoritative. Window top margin remains disabled as requested earlier.

No resolution, screen arrangement or system fullscreen preference is changed. Automated geometry/selection tests are separate from physical display disconnect/reconnect and sleep/wake verification.

## 8. Idle work and lifecycle

Disabling Window Top Margin now tears down global mouse hooks, per-app AX observers, retry timer and previews; it retains only the subscriptions needed to re-enable the feature. With the feature enabled, accessibility retry uses ten seconds with tolerance and never prompts automatically. Meeting elapsed time updates only while a meeting view has a visible consumer, and derives from start time so hidden time and sleep do not cause drift. Meeting discovery is coalesced, runs off the main UI queue, uses a fifteen-second idle / three-second active cadence and responds to application lifecycle/activation events. Existing controls are unchanged. Meeting/message monitor starts are idempotent; timers have tolerances. Occlusion/hidden-view visibility publishing deduplicates state and rejects obsolete queued callbacks. Shutdown cancels owned recovery/monitor work.

The full suite exposed an existing FSEvents callback lifetime crash in the download monitor (`Notchie-2026-10-30-160108.ips`, queue com.dynamicnotch.download.monitor). The old callback used an unretained watcher pointer after stop/deinit. The stream now retains a separate invalidatable callback context, avoiding a watcher retain cycle and allowing queued callbacks to drain safely. A repeated start/publish/write/stop/release regression exercises a live stream, with no user browser-database reads.

A short old-process CPU sample was collected during development, but other test hosts were active; it is not a controlled before/after energy benchmark. Final idle samples describe only the observed installed process, not battery-life guarantees.

## Name and installation

Display/bundle names were already Notchie; Finder's installed bundle and executable still said DynamicNotch. Installer now targets `/Applications/Notchie.app`, validates both current and legacy bundle IDs before replacement, backs up either existing installation, unregisters the old path and registers the new one. The executable is Notchie; the Xcode project/scheme/module and com.Jackson.DynamicNotch identifier remain for compatibility. Only a retired generated DynamicNotch executable is omitted from the staged copy if incremental builds leave it beside Notchie; user data and source artifacts are not removed. Local instructions/README now use the installed name. Installation still goes through scripts/install-local.sh and verifies the exact final artifact.

## Validation

Regression coverage includes deferred/expired ordinary alerts, critical timer/system preemption, ending expanded activity, transition-time removal, stable ties, pending expansion cancellation/menu protection, display fit/negative origins/automatic fallback, disabled constraint monitor lifecycle, meeting visible-consumer timing, and live filesystem stream shutdown. Existing tests that explicitly required ordinary interruptions now exercise urgent interruption or explicitly collapse before testing compact press scaling. Initial compile failures and the FSEvents crash log remain in evidence. Final build/test/install/runtime identity is recorded below and in the authoritative trackers.
